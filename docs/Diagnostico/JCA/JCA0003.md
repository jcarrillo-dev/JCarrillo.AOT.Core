# Diagnóstico JCA0003: Uso de params T[] en .NET 8.0 con allocations

## 1. Metadatos del Diagnóstico
- **Gravedad**: Warning
- **Categoría**: Performance
- **Objetivo**: Operador `Concat` (con parámetro `params`) en el runtime .NET 8.0

## 2. Descripción
Bajo el runtime .NET 8.0, la especificación del compilador implementa el paso de parámetros múltiples mediante la palabra clave `params` instanciando un array temporal (`T[]`) en el heap. Al invocar sobrecargas que aceptan `params` (como la concatenación de múltiples consultas), se genera una asignación implícita en heap por cada llamada.

En mediciones empíricas bajo .NET 8.0 JIT, la llamada `Concat` con 5 elementos mediante `params` aloca 56 B **(medido)** en heap.

## 3. Mitigación y Remediación
Para eliminar la asignación en heap, se plantean las siguientes soluciones:
1. **Actualizar el runtime del proyecto a .NET 9.0 o superior**: En .NET 9.0 y superiores, el compilador y el JIT optimizan el paso de parámetros `params` utilizando tipos `ReadOnlySpan<T>` en pila, reduciendo la asignación a 0 B **(medido)**.
2. **Utilizar sobrecargas de llamada directa**: Evitar el uso de la firma con `params` en .NET 8.0 utilizando métodos que reciban estructuras estáticas directamente sin requerir la creación de un array intermedio.

## 4. Ejemplos de Código

### Código no recomendado (Bajo .NET 8.0, genera allocations)
```csharp
// Genera una asignación temporal de 56 B en heap para pasar los argumentos
using var query = q1.Concat(q2, q3); 
```

### Código recomendado (Cero Asignaciones)
Para entornos que requieren soporte de .NET 8.0, se propone evitar la creación implícita del array temporal mediante llamadas estructuradas directas o actualizando a una versión de TFM compatible con la optimización de spans del compilador:
```csharp
// Actualizando el Target Framework Moniker (TFM) a net9.0 o superior:
// El compilador optimiza la firma mediante ReadOnlySpan<T> en pila (0 B de asignación)
using var query = q1.Concat(q2, q3); 
```

## 5. Supresión de la Advertencia
La advertencia se puede suprimir localmente en el archivo fuente en secciones donde las asignaciones no afecten la latencia crítica:

```csharp
#pragma warning disable JCA0003
using var query = q1.Concat(q2, q3);
#pragma warning restore JCA0003
```

O de forma global en el archivo de configuración del proyecto (`.csproj`):
```xml
<NoWarn>$(NoWarn);JCA0003</NoWarn>
```
